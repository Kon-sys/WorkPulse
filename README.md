# WorkPulse

Корпоративная система учёта рабочего времени и анализа активности сотрудников.

WorkPulse помогает руководителям и HR-специалистам видеть структуру рабочего дня: продуктивную активность, простои, перерывы и отклонения от установленного графика. Система объединяет данные рабочих станций в отчёты и аналитические панели, сокращая ручную работу с табелями и разрозненными файлами.

Проект ориентирован на организации с офисным, удалённым и гибридным форматом работы.

## Статус проекта

Проект находится на этапе подготовки к реализации. Выполнены анализ предметной области, моделирование бизнес-процессов, разработка требований, проектирование архитектуры и выбор технологического стека.

Описанные ниже возможности составляют проектный объём системы. Их реализация и инструкции по запуску будут добавляться по мере разработки.

## Какую задачу решает WorkPulse

При ручном учёте рабочего времени информация распределяется между табелями, сообщениями сотрудников и отчётами руководителей. HR приходится сверять данные из нескольких источников, а причины простоев и отклонений от графика остаются неочевидными.

WorkPulse предусматривает единый цикл обработки данных:

1. Агент на рабочей станции фиксирует события активности.
2. Сервер учитывает рабочие сессии и перерывы.
3. Аналитический сервис применяет настроенные политики мониторинга.
4. Руководители и HR получают отчёты по сотрудникам и подразделениям.

Данные активности используются для анализа рабочего времени. Они не заменяют оценку качества выполненной работы.

## Планируемые возможности

- Автоматическая фиксация начала и окончания рабочей сессии.
- Учёт обеденного перерыва отдельно от простоев.
- Сбор метаданных об использовании приложений и веб-ресурсов.
- Классификация активности на продуктивную, нецелевую и нейтральную.
- Выявление простоев и отклонений от рабочего графика.
- Журнал нарушений с фильтрами, деталями и комментариями.
- Отчёты и KPI по сотрудникам и подразделениям.
- Сравнение показателей за разные периоды.
- Экспорт отчётов в PDF и XLSX.
- Настройка графиков, категорий активности и политик мониторинга.
- Ролевое разграничение доступа.
- Интеграция с корпоративными HRM- и ERP-системами.

## Пользователи системы

| Роль | Основные задачи |
|---|---|
| HR-специалист | Учёт рабочего времени, настройка политик, анализ отчётов и отклонений |
| Руководитель подразделения | Анализ показателей своей команды |
| Топ-менеджмент | Просмотр сводной аналитики по подразделениям |
| Специалист по информационной безопасности | Контроль ограничений мониторинга и доступа к данным |
| Системный администратор | Управление пользователями, ролями и техническими настройками |
| Сотрудник | Участие в учёте рабочей сессии и перерывов, получение уведомлений |

## Архитектура

Система спроектирована как клиент-серверное приложение. Архитектурная модель описана на уровнях C4: системный контекст, контейнеры, компоненты и классы аналитической логики.

| Компонент | Назначение |
|---|---|
| Web Application | Пользовательский интерфейс, отчёты, журнал и настройки |
| Client Agent | Сбор событий активности на рабочей станции |
| API Application | Серверная бизнес-логика и разграничение доступа |
| Analytics Service | Классификация активности, выявление простоев, расчёт KPI |
| Notification Service | Уведомления о нарушениях и технических событиях |
| Integration Adapter | Обмен кадровыми данными с HRM/ERP |
| Database | Хранение событий, сессий, политик и результатов анализа |

Взаимодействие веб-приложения и агента с API предусматривается через HTTPS с передачей данных в формате JSON.

Аналитическая обработка выделена в отдельный сервис, чтобы ресурсоёмкие расчёты можно было развивать и масштабировать независимо от пользовательского API. Конкретная схема развёртывания будет определена при реализации.

## Технологический стек

| Область | Технологии |
|---|---|
| Frontend | React, TypeScript |
| Backend | C#, ASP.NET Core |
| Агент рабочей станции | .NET Worker Service |
| База данных | PostgreSQL |
| API | REST, JSON, HTTPS |
| Аутентификация и доступ | JWT, RBAC |

PostgreSQL выбрана для хранения взаимосвязанных корпоративных данных и выполнения аналитических запросов. ASP.NET Core используется как основа серверного API и фоновой обработки, а React с TypeScript — для интерфейсов отчётности и настройки системы.

## Конфиденциальность

В основу проекта заложен принцип privacy-by-design:

- сбор данных ограничивается задачами учёта рабочего времени;
- правила мониторинга должны быть доступны и понятны сотрудникам;
- доступ к информации определяется ролью пользователя;
- сроки хранения задаются политиками организации;
- изменения политик, прав доступа и классификации подлежат аудиту;
- постоянная запись экрана и скрытое наблюдение не предусматриваются.

Вопрос о контекстной фиксации рабочего места при нарушениях остаётся открытым. Её включение в реализацию требует отдельного определения условий, уведомлений, доступа и сроков хранения.

## Требования к качеству

В проектной спецификации установлены следующие целевые показатели:

| Показатель | Требование |
|---|---|
| Масштаб организации | От 50 до 5000 сотрудников |
| Отклик интерфейса на основные действия | Не более 1 секунды при штатной нагрузке |
| Формирование стандартного отчёта по подразделению | Не более 5 секунд при штатной нагрузке |
| Доступность серверной части | Не менее 99% в рабочее время организации |
| Потеря соединения агента с сервером | Сохранение целостности и последующая синхронизация данных |

Эти значения являются целями проектирования. Подтверждение нагрузочными и эксплуатационными проверками предстоит выполнить после реализации.
