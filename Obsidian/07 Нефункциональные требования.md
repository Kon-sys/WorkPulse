# Нефункциональные требования

Источник: [[ЛР4 — извлечённый текст]], таблица 2.2. Все исходные идентификаторы сохранены.

- **UI-1** — Интерфейс программного средства должен быть реализован на основе веб-технологий и обеспечивать корректное отображение в современных браузерах: Google Chrome, Mozilla Firefox, Microsoft Edge.
- **UI-2** — Интерфейс должен быть адаптирован для разных категорий пользователей: HR-специалиста, руководителя подразделения, топ-менеджмента, специалиста по ИБ и системного администратора.
- **UI-3** — Доступ к основным функциям системы, включая просмотр отчетов, журнал нарушений и настройку политик мониторинга, должен осуществляться не более чем за три перехода от главной страницы.
- **UI-4** — Время реакции интерфейса на основные пользовательские действия, включая открытие разделов, применение фильтров и просмотр карточки нарушения, не должно превышать 1 секунду при штатной нагрузке.
- **SI-1** — Система должна взаимодействовать с реляционной базой данных для хранения сведений о пользователях, рабочих сессиях, активности, нарушениях, отчетах и политиках мониторинга.
- **SI-2** — Система должна обеспечивать возможность интеграции с корпоративными HRM- и ERP-системами для получения сведений о сотрудниках, подразделениях и должностях.
- **SI-3** — Система должна поддерживать экспорт аналитических отчетов в форматы PDF и XLSX.
- **SI-4** — Система должна обеспечивать передачу данных между клиентским агентом и серверной частью по защищенному каналу связи.
- **QA-1 (Надежность)** — Программное средство должно сохранять целостность данных при временной потере соединения между клиентским агентом и сервером.
- **QA-2 (Безопасность)** — Доступ к функциям системы должен быть ограничен механизмом ролевой авторизации.
- **QA-3 (Конфиденциальность)** — Система должна минимизировать сбор чувствительных данных и использовать только те сведения, которые необходимы для учета рабочего времени и анализа активности.
- **QA-4 (Производительность)** — Система должна обеспечивать формирование стандартного отчета по одному подразделению за выбранный период не более чем за 5 секунд при штатной нагрузке.
- **QA-5 (Масштабируемость)** — Архитектура программного средства должна поддерживать возможность использования системы в организациях с численностью сотрудников от 50 до 5000 человек.
- **QA-6 (Аудит)** — Система должна сохранять историю изменений политик мониторинга, прав доступа и настроек классификации активности.
- **QA-7 (Доступность)** — Время доступности серверной части системы должно составлять не менее 99 % в рабочее время организации.
- **QA-8 (Удобство сопровождения)** — Система должна позволять изменять справочники приложений, сайтов и категорий активности без внесения изменений в программный код.

## Что требуется для проверки

«Штатная нагрузка» не определена численно. Нужно зафиксировать количество одновременных пользователей, поток событий, объём БД, период отчёта и условия измерения. Цель 50–5000 сотрудников не определяет автоматически число одновременных подключений.

UI-4 (1 секунда) и QA-4 (5 секунд) относятся к разным операциям; взаимодействие длительного расчёта с откликом интерфейса ещё предстоит определить. Для QA-7 нужны окно рабочего времени, метод измерения и исключения. Для QA-1 нужны правила буферизации, повторной отправки и устранения дубликатов.
