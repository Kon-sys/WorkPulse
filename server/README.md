# WorkPulse: бизнес-логика ЛР8

Ядро учёта рабочих сессий и анализа активности на C#/.NET 10. Оно использует утверждённые правила WorkPulse и не зависит от HTTP, пользовательского интерфейса или СУБД.

## Быстрый запуск

Из корня проекта в PowerShell:

```powershell
# Один раз: локальная установка SDK Microsoft, интернет нужен только здесь.
.\server\setup.ps1

.\server\run.ps1 -Action build
.\server\run.ps1 -Action test
.\server\run.ps1 -Action demo
```

Если SDK 10.0.401 уже установлен, `setup.ps1` не нужен. Локальный SDK расположен в `tmp/dotnet`, не добавляется в системный PATH и не попадает в Git. Скрипт запуска предпочитает этот SDK, иначе использует установленный `dotnet`. `server/global.json` закрепляет версию; допускает последующие исправления той же SDK feature band. Внешних NuGet-пакетов нет: `NuGet.Config` очищает источники только для этого решения. Сборка и демонстрация после установки SDK работают без сети.

Тесты – самостоятельный консольный проверочный проект: 19 групп сценариев, в том числе 100 случайных шкал со стабильным seed. `run.ps1 -Action test` возвращает ошибку при любой неуспешной проверке. `dotnet test` не используется: тестового SDK/адаптера NuGet здесь нет.

## Структура

| Проект / каталог | Назначение |
|---|---|
| WorkPulse.Domain | Агрегат WorkSession, перерывы, неизменяемая политика и значения предметной области |
| WorkPulse.Application | Реконструкция шкалы, классификация, обнаружение нарушений, сценарий анализа и порт хранилища |
| WorkPulse.Demo | Консольная демонстрация и адаптер хранилища в памяти |
| tests/WorkPulse.Tests | Проверки бизнес-правил и свойств временной шкалы |
| design | Редактируемые исходники UML, алгоритмов и чертежа |

## Что реализовано

- Начало сессии по login / focus / input; опубликованная политика той же организации фиксируется при старте.
- Завершение командой manual / logout. Окончание расписания само не закрывает сессию.
- Последовательные непересекающиеся перерывы; не более одного обеда. Завершение сессии закрывает открытый перерыв в тот же момент.
- Полуоткрытые интервалы `[start, end)`, абсолютные моменты времени и ночные смены.
- Проверка принадлежности событий организации, сотруднику, набору устройств и сессии.
- Дедупликация по устройству и client_event_id. Различающийся payload при том же ключе отклоняется.
- Детерминированная реконструкция по времени возникновения, независимо от порядка доставки.
- Единая шкала сотрудника без сложения времени одновременно работающих устройств.
- Неизвестный ресурс классифицируется как neutral; потеря покрытия данных – unknown.
- Простои подтверждаются idle всех ожидаемых устройств. Подтверждённая активность любого актуального устройства имеет приоритет над idle остальных.
- Обед и разрешённое отсутствие перекрывают автоматическую классификацию. Отсутствие не создаёт нарушения; превышение обеда проверяется отдельно.
- Нарушение возникает при **строгом** превышении лимита непрерывной категории. Изменение ресурса при той же категории не разрывает интервал; обед/отсутствие/unknown разрывают его.
- Каждый пересчёт создаёт новый AnalysisRun с версией алгоритма и сроком актуальности сигналов; прошлый результат сохраняется.

Подробности и границы предположений: [algorithms.md](design/algorithms.md). UML и чертёж: [design/README.md](design/README.md).

## Связь с ЛР7 и дальнейшими этапами

SQL-миграции `database/migrations` остаются единственным источником схемы PostgreSQL. В ЛР8 ядро проверяется без БД; оно не создаёт таблицы и не выполняет EF migrations или EnsureCreated. Адаптер PostgreSQL, отображение сущностей, транзакции и tenant/RBAC-контекст будут реализованы при подключении сервера. `IAnalysisRunStore` пока имеет только демонстрационный адаптер в памяти.

Нет HTTP API, реального агента, подключения UI, автоматического фонового пересчёта, KPI, опозданий/раннего ухода и настоящей отправки уведомлений. Общая сессия не закрывается автоматически при logout одного из нескольких устройств: завершение всей сессии является отдельной командой.

## Инструменты

- [.NET SDK 10](https://dotnet.microsoft.com/en-us/download/dotnet/10.0), локальная установка через [официальный скрипт Microsoft](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-install-script).
- [PlantUML MIT](https://plantuml.com/download) для локального построения UML; Java уже установлен. Инструмент не является зависимостью приложения.

Формальный DOCX-отчёт ЛР8 не создан. Для основной надписи чертежа требуется сверка с образцом преподавателя: методичка отсылает к отсутствующему заданию ЛР3 другого комплекта.
