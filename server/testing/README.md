# ЛР10 – тестирование WorkPulse

Рабочая ветка: feature-testing. Разработка расширена по решению пользователя от 14.10.2026: до завершения работы необходимо реализовать и проверить все 32 FR. Отчёт DOCX формируется только после полного прогона и отдельной команды.

## Запуск модульных тестов

Из корня проекта:

```powershell
.\server\run.ps1 -Action test
.\server\run.ps1 -Action coverage
.\server\coverage-summary.ps1
```

71 xUnit-тестов проходят. Существующие 19 групп алгоритмических проверок сохранены в KernelTests.cs; добавлены проверки ролей, политик, KPI, графика, валидации API и XLSX. TRX и Cobertura записываются в игнорируемый tmp/lr10. [coverage-summary.md](coverage-summary.md) содержит реальный снимок покрытия модульными тестами всех четырёх сборок; HTTP и UI не включены в это измерение. Низкое модульное покрытие SQL/HTTP-адаптеров нельзя заменять процентом Domain.

## Интеграционные проверки

Сначала поднять Docker Desktop (Engine running), затем БД и API по [инструкции](../api-guide.md).

```powershell
.\database\db.ps1 -Action up
.\database\db.ps1 -Action validate
.\server\api.ps1 -Action run
# Другой терминал; Python 3:
python server/tests/lr10-integration.py
```

Прогон использует синтетические записи, выполняет 29 проверок ЛР9 и дополнения графика, отчётов, изоляции и экспорта. Требуется существующий tmp/api-demo-password.txt после seed. Секреты не выводятся. Результаты и файлы экспорта сохраняются в tmp/lr10.

## Браузер

При работающих API и UI на 4173, установленном Chrome:

```powershell
npm --prefix ui-prototype ci
npm --prefix ui-prototype run check
npm --prefix ui-prototype run build
npm --prefix ui-prototype run test:sites
npm --prefix ui-prototype run test:live
```

test:live проверяет вход, разделы, сохранённый анализ, CSV, новые отчёты, PDF/XLSX, сравнение, мобильное переполнение и ограничения HR. Он требует реальную локальную БД с синтетическими данными; не подменяет ответы API. При отсутствии Chrome можно установить Chromium через Playwright и изменить channel в сценарии.

## Согласованные правила

FR2-2 изменён: завершение сессии выполняется явно. График, неизвестность и Logout устройства не закрывают общую сессию. Оригинальное требование сохранено в [матрице](requirements-matrix.md).

График публикуется вместе с версией политики: дни недели, начало/конец, ночной переход, IANA time zone, допуски по умолчанию 300 секунд. При неоднозначных/несуществующих локальных временах DST оценка графика неизвестна. Выбор смены ищет текущую и предыдущую локальную дату; начало допускается в пределах четырёх часов до смены. Отсутствующая или неоднозначная смена не считается нарушением.

Опоздание требует Login/Focus/Input на границе начала; ранний уход – закрытую сессию и известное покрытие конца. Unknown и разрешённое отсутствие не порождают ранний уход. Доли Productive/NonTarget/Idle рассчитываются среди известного времени без lunch/authorized absence; покрытие = known/(known+unknown). Нулевой знаменатель – null. Соблюдение графика = доля соответствующих графику полностью включённых сессий среди сессий с подтверждёнными границами.

Отчёт выбирает последний завершённый анализ каждой сессии, клиппирует его по периоду и добавляет Unknown для непокрытых частей сессии. Время вне сессий не считается простоем. Подразделения агрегируют время людей, а не суммируют пересчёты. Период до 93 дней; более 1000 сотрудников/10000 сессий отклоняется с просьбой сузить выборку. UI сравнивает предыдущий период той же длины; разница долей указана в процентных пунктах.

## Изменения схемы и библиотек

V010 добавляет допуски опоздания и раннего ухода. Исходные V001–V009 не изменены. График использует существующую schedule_days, отчёты – существующие сессии/анализы; новая изоляция организаций не обходится.

Экспорт: PDFsharp 6.2.4 и ClosedXML 0.105.1 (MIT). System.Security.Cryptography.Pkcs 10.0.13 закреплён для устранения уязвимой транзитивной версии. На Windows PDF использует Arial из системных Fonts. На Linux требуется WORKPULSE_REPORT_FONT с путём к Unicode TTF; шрифт не распространяется в репозитории. Нет платного сервиса генерации.

Тесты: xUnit 2.9.3, VS runner 4.0.1, Microsoft.NET.Test.Sdk 18.11.0, Coverlet collector 10.1.0, Playwright 1.64.0. Источники: https://learn.microsoft.com/dotnet/core/testing/unit-testing-code-coverage ; https://github.com/coverlet-coverage/coverlet ; https://docs.pdfsharp.net/PDFsharp/Topics/Fonts/Font-Resolving.html ; https://docs.closedxml.io/ .

## Статус

71 модульный тест, 52 проверки HTTP, браузерный прогон, проверки БД и настоящий агент прошли. Сопоставление всех 32 FR приведено в матрице; FR2-2 проверяется в согласованной редакции. Полные результаты: [verification.md](verification.md). DOCX пока не создан.

Реальный агент при работающем API: `.\agent\test-native.ps1` (Python 3; можно передать -PythonPath). Скрипт сохраняет пользовательскую конфигурацию и отзывает тестовое устройство после успешного прогона. После проверки остановите API/UI через Ctrl+C и выполните `.\database\db.ps1 -Action down` без удаления тома. Для повторных прогонов учитывайте ограничение входа 20 попыток в минуту с одного адреса: несколько быстрых повторов могут потребовать паузы.
