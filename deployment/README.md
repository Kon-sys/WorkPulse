# Развёртывание WorkPulse

## Назначение и среда
Документ предназначен для технического специалиста, развёртывающего учебную версию WorkPulse на локальном компьютере. Поставка – исходники из репозитория, а не готовый установщик. PostgreSQL работает в Docker, API и UI запускаются отдельными процессами, агент – в интерактивной сессии Windows. Рабочий маршрут: агент → API → PostgreSQL → веб-интерфейс.

Проверенная конфигурация: Windows, Docker Engine 29.2.0 с Linux containers, PostgreSQL 18.6, Flyway Community 13.10.0, .NET SDK 10.0.401, Node.js/npm и Chrome. Рекомендуемый резерв для учебной машины – 4 ядра, 8 ГБ RAM и 10 ГБ свободного диска. Это рекомендация для локального запуска, минимальные аппаратные требования и нагрузка 5000 сотрудников не измерены. Интернет нужен для первой загрузки образов и зависимостей; локальная работа возможна после их загрузки.

## Состав поставки
`database` содержит compose.yaml, bootstrap, миграции V001–V010, seed и проверки. `server` содержит Domain, Application, Infrastructure, API, тесты и PowerShell-команды. `ui-prototype` – рабочий React-клиент с package-lock.json. `agent` – Windows-сборщик и пример конфигурации. `deployment` – эти руководства и проверки ЛР11. Локальные .env, appsettings.Local.json, токены, бэкапы, tmp и Obsidian не входят в публичную поставку.

Репозиторий: https://github.com/Kon-sys/WorkPulse. Используйте ревизию с влитыми изменениями ЛР10 и ЛР11. После клонирования откройте PowerShell в корне. Распаковка в системную директорию не требуется: выберите пользовательский каталог. Git нужен только для получения исходников, Python и Playwright – для дополнительных проверок, редактор и Figma не требуются конечному пользователю.

## Последовательность установки
Установите Docker Desktop, включите Linux containers и дождитесь Engine running. Установите Node.js/npm. Запустите следующие команды из корня проекта:

```powershell
.\server\setup.ps1
.\database\setup.ps1
.\database\db.ps1 -Action up
.\database\db.ps1 -Action seed
.\server\run.ps1 -Action build
.\server\api.ps1 -Action seed
npm --prefix ui-prototype ci
```

setup сервера устанавливает SDK в tmp/dotnet без постоянного изменения PATH. setup БД создаёт случайные пароли в database/.env, не перезаписывая существующий файл. up ожидает готовность PostgreSQL и применяет недостающие миграции. seed предназначен для синтетических данных двух демонстрационных организаций. Повторный seed пользователей не сбрасывает пароли существующих записей.

В трёх отдельных терминалах запускаются API, UI и позднее агент. Сначала API и UI:

```powershell
.\server\api.ps1 -Action run
npm --prefix ui-prototype run dev -- --host 127.0.0.1 --port 4173
```

Первая команда остаётся в первом терминале, вторая – во втором. Адрес интерфейса http://127.0.0.1:4173, API http://127.0.0.1:5080. Vite проксирует /api на API. Не закрывайте терминалы до завершения демонстрации. Эта схема использует сервер разработки Vite; для публикации нужен отдельный хостинг статической сборки и прокси HTTPS.

## Конфигурация и вход
БД доступна на 127.0.0.1:55432. В database/.env находятся DB_PORT, DB_OWNER_PASSWORD и DB_APP_PASSWORD. API подключается только как workpulse_app; owner используется для миграций и резервирования. Не передавайте строку подключения браузеру. Смена значения пароля в .env не меняет пароль существующего PostgreSQL volume: требуется административная смена пароля и синхронное обновление секрета.

При seed создаются admin@example.test, hr@example.test, manager@example.test и employee@example.test в организациях Север и Юг. Общий локальный пароль находится в tmp/api-demo-password.txt. Прочитайте его локально и введите в форму входа; не включайте его в отчёт, скриншоты и Git. Если этот файл потерян, повторное заполнение пользователей не восстанавливает прежний пароль. Существующую БД и volume ради пароля удалять нельзя.

Для экспорта PDF на Windows используется Arial. На Linux потребуется Unicode TTF, путь к которому задаётся WORKPULSE_REPORT_FONT. Часовой пояс политики задаётся идентификатором IANA, например Europe/Minsk. Серверные временные отметки передаются в UTC, график интерпретируется в часовом поясе политики. Cookie HttpOnly и CSRF защищают пользовательские запросы, устройства используют отдельные токены.

## Подключение агента
Администратор входит в Настройки и регистрирует устройство конкретного сотрудника. Токен показывается только при выдаче или ротации. Скопируйте agent/appsettings.example.json в agent/appsettings.Local.json и укажите выданный токен, serverUrl http://127.0.0.1:5080 и отдельный bufferDirectory. pollSeconds по умолчанию 2, idleSeconds 30. Порог датчика и допустимый лимит простоя политики имеют разные назначения.

```powershell
Copy-Item .\agent\appsettings.example.json .\agent\appsettings.Local.json
.\agent\run.ps1 -Action build
.\agent\run.ps1 -Action run
```

Агент собирает имя активного процесса и состояния ввода. Он не считывает нажатые символы, содержимое сообщений, заголовки окон, адреса сайтов или скриншоты. Запуск ручной, служба и автозапуск не устанавливаются. Одному устройству нужен отдельный буфер и один работающий процесс. При ротации сначала доставьте очередь, остановите агент и подготовьте новый каталог для новых учётных данных.

## Резервное копирование и восстановление
Перед резервированием завершите демонстрационные операции и остановите агент. Команда backup создаёт custom-format архив внутри контейнера и копирует бинарный файл без перенаправления PowerShell:

```powershell
.\database\db.ps1 -Action backup
```

Файл находится в database/backups. Храните архив защищённо: он содержит сведения пользователей, хеши учётных данных и рабочую историю. Для учебного восстановления используйте новую пустую БД, имя которой ещё не занято. Рабочую workpulse не перезаписывайте. Вместо ИМЯ.dump укажите фактически созданный файл:

```powershell
docker compose --project-directory database exec -T postgres createdb -U workpulse_owner workpulse_restore
docker compose --project-directory database cp database/backups/ИМЯ.dump postgres:/tmp/restore.dump
docker compose --project-directory database exec -T postgres pg_restore -U workpulse_owner -d workpulse_restore --exit-on-error /tmp/restore.dump
docker compose --project-directory database exec -T postgres psql -U workpulse_owner -d workpulse_restore -c "SELECT count(*) FROM workpulse.organizations;"
```

pg_dump не сохраняет серверные роли и их пароли. На новом сервере сначала создайте bootstrap-роли через стандартную установку. Восстановление выполняется owner, приложение остаётся ограниченной ролью. Контроль числа организаций – первичная проверка; ЛР11 дополнительно сравнивает количество строк во всех 29 таблицах, выполняет проверки ограничений и RLS. Совпадение количества строк не является побайтовой проверкой содержимого.

api.ps1 ориентирован на базу workpulse. Переключение штатного приложения на произвольное имя восстановленной базы не выполняется этим примером: оно требует настройки строки подключения и отдельной проверки API. Для этой лабораторной проверяется восстановление в независимую БД, а не аварийная подмена рабочей базы. Производственный регламент RPO/RTO и внешнее хранение бэкапов не подтверждены локальным опытом.

## Проверка установки и остановка
Проверьте /health/live, откройте UI и войдите. Наличие страницы входа подтверждает UI, но для проверки цепочки откройте сотрудников, зарегистрируйте тестовое устройство, получите события и выполните анализ новой сессии. Затем сформируйте отчёт и проверьте PDF/XLSX. Для дополнительных проверок используйте команды ниже:

```powershell
.\database\db.ps1 -Action validate
.\database\db.ps1 -Action test
.\server\run.ps1 -Action test
.\agent\run.ps1 -Action test
python .\server\tests\lr10-integration.py
npm --prefix ui-prototype run test:live
.\deployment\verify.ps1
python .\deployment\measure.py
```

HTTP-проверки требуют работающий API, браузерные – также UI. verify.ps1 создаёт отдельный Compose-проект с отдельным volume, использует порт 55433, восстанавливает БД и проверяет перезапуск. Он оставляет тестовый volume для воспроизводимости и останавливает свои контейнеры. measure.py выполняет 30 последовательных запросов каждого типа и сохраняет результаты в tmp/lr11; нагрузку многопользовательской эксплуатации он не моделирует.

Для остановки нажмите Ctrl+C в терминалах агента, UI и API, затем выполните database/db.ps1 -Action down. Volume сохраняется. Для повторного запуска достаточно up, API, UI и агента с прежними секретами. Не применяйте down -v как обычную остановку. Если Docker недоступен, сначала проверьте Engine running; если порт занят, выберите другой порт БД и согласованно обновите конфигурацию. При checksum mismatch восстановите применённую миграцию из Git и создайте новую миграцию вместо сокрытия расхождения через repair.
